How Muse learns a tool

01Why Muse knows device.health

On each connection, the SDK advertises tool names, descriptions and parameters. Muse receives the catalog and can request a tool by name. The stock catalog lives in executor.py; our runtime can supply its own catalog and dispatcher.

03Discovery, indexing and execution

Load an explicit list of installed modules. Each supplies a name, version, description, parameter schema, timeout and handler. Validate these and build a name → handler index. The adapter exports this catalog in the SDK’s command format; no search database is needed.

The worker runs handlers and behavior routines, validates inputs, serializes hardware actions and handles start/stop cleanup. Freeze the catalog per connection; re-register on controlled restart. Live catalog replacement is unverified.

05Build this first

  1. Create our package: registry.py, runtime.py, muse_adapter.py, ipc.py and tools/status.py in msdos-reachy. First tool: read-only reachy.status; first local command: list indexed tools.
  2. Test with a fake VM: catalog registration, validation, IDs, payload limits, handler deadlines and reconnects. Implement bounded IPC for tools, text, events and media.
  3. First live checkpoint: Muse calls reachy.status successfully; a typed runtime request receives its matching reply. Then add speech, microphone turns and gestures after the pending hardware checks with an observer.
